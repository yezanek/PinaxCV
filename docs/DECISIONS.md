# PinaxCV Architecture Decisions

## ADR-001 — Standalone-first

PinaxCV v1 is Linux/Windows desktop only. This avoids recurring hosting costs before product-market evidence exists.

## ADR-002 — SQLite in v1

SQLite is the v1 persistence implementation. PostgreSQL is reserved for a future SaaS phase.

## ADR-003 — Domain independent of storage

The domain must not depend on SQLite or PostgreSQL. Persistence is behind application/repository boundaries.

## ADR-004 — Tauri as adapter

Business logic does not live in Tauri commands.

## ADR-005 — HTML export in v1

PinaxCV exports a single self-contained HTML file from `ResolvedCv`, independently of PDF rendering. It is intended for personal websites.

## ADR-006 — Separate PDF and HTML templates

PDF and HTML share semantic content but have different layout requirements. HTML is not generated by converting the PDF.

## ADR-007 — macOS deferred

macOS support is a product-validation decision, not a v1 requirement.

## ADR-008 — SaaS deferred

Accounts, HTTP API, PostgreSQL, synchronization, multi-tenancy, billing, and hosted infrastructure are not implemented until explicitly justified by demand.

## Open decisions

- exact persistence interface shape;
- exact HTML CSS/template design;
- exact PDF text extraction crate;
- Typst version/API;
- font licensing/final set;
- application license;
- German UI timing;
- future SaaS synchronization model.
